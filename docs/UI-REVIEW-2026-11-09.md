# UIレビュー：85点から95点にするための改善点

実施日：2026年11月9日
対象：ShinroKensakuDesktop / master（9725e27）
確認方法：

- 全画面のXAMLとViewModelを読み、表示される文字・部品・余白を洗い出した。
- ダッシュボード・進路グラフ・年度比較は、実データ（11年度・6,020件）を1200×800のウィンドウで確認した。
- 検索・設定・ダーク表示は、`Run-App.ps1 -Verify -Render`で架空データを描画して確認した。検索結果は氏名を含むため、実データでは表示していない。
- Nielsen Norman Group（NN/g）、Microsoft（Windows／Fluent）、W3C（WCAG）、デジタル庁デザインシステム、Datawrapperの資料を調べ、判断の根拠にした（出典は末尾）。

## 0. 結論

### 85点の理由（維持するもの）

- WPF UI（Fluent）の部品でそろえていて、カード・見出し・余白の見た目に統一感がある。
- ライト・ダーク・ハイコントラストに対応し、表見出しのコントラストを自動テストで検証している。
- グラフの系列色を「全期間の件数順」で固定していて、表示範囲を変えても色が動かない。
- 検索表は3列固定・仮想化・Enter/Esc・条件変更時のCSV無効化など、操作の安全性が高い。
- 主なボタンと入力欄に`AutomationProperties.Name`が付いている。

### 95点に届かない理由（3つ）

1. **説明を「隠した」が「不要」にはしていない。**
   前回のコミット（f52fca8）で説明文をⓘに移し、画面の文字は減った。しかしⓘは5画面で14個ある。
   中身には「件数は同じ生徒の複数回受験を含む」「点をクリックすると明細が開く」「パスワードは空欄なら引き継ぐ」のような、
   知らないと数字を誤解したり機能を見落としたりする情報が入っている。NN/gは、ほとんどの利用者はⓘを開かないこと、
   ルールや制約をⓘに入れてはいけないことを指摘している。
2. **意味を文字で区別していて、色とアイコンの決まりがない。**
   進学／就職、増減、合否、接続状態、警告が、ほぼ文字だけで表されている。色を使っているグラフでは、
   同じ青が「年度別の推移」では「進学」、すぐ下の「受験方法別の推移」では「就職」を表していて、
   色の意味が同じ画面の中で入れ替わる。
3. **状態の出し方が画面ごとに違う。**
   読み込み中・エラー・最終更新・再検索の案内が、右上の灰色の小さい文字、表の下、ボタンの横などに散らばっている。
   エラーも補足と同じ灰色の小さい文字で表示されるので、気づきにくい。

### 改善の原則

このドキュメントの改善案は、すべて次の5つの原則で判断している。

| #  | 原則                     | 具体的には                                                                                         |
|----|--------------------------|----------------------------------------------------------------------------------------------------|
| P1 | 説明を書く前に、説明が要らない形にする | 指標名・並び順・グループ分け・置き場所で意味を伝える。ⓘは「知らなくても操作できる補足（定義・算出方法）」だけに使う |
| P2 | 意味ごとに色とアイコンを1つに決め、全画面で守る | 進学＝青＋角帽アイコン、就職＝橙＋かばんアイコン、合計＝灰色の破線。色は必ず文字か形とセットで使う |
| P3 | 状態は決まった3つの部品で出す | 対応が必要なこと→InfoBar、処理中→ProgressBar・スケルトン、参考情報（最終更新など）→小さいキャプション |
| P4 | 操作は見えるラベルで示す | ナビゲーションと画面ごとの操作はテキスト付きにする。アイコンだけでよいのは、再読み込み・ダウンロード・中断のような定番だけ |
| P5 | 数字には比べる基準を添える | 前年度比・構成比を添える。「508」だけで終わらせない |

### 2.2 色の体系（意味の色）

#### 今の問題

- **同じ色が別の意味になる（重要度：高）。**
  `ChartData.MethodTrend`は受験方法を件数順にパレットへ割り当てる。実データでは件数1位の受験方法が「就職」なので、
  「受験方法別の推移」の青は「就職」、橙は「指定校推薦」になる。すぐ上の「年度別の推移」では青が「進学」、橙が「就職」なので、
  スクロールすると色の意味が入れ替わる。
- 色が付いているのはグラフだけで、KPIカード・ダッシュボードの一覧・年度比較の表・検索結果では、進学と就職を文字だけで区別している。
- 増減・合否・接続の成否・警告に色やアイコンがない。

#### 改善案：意味の色を決めて、全画面で使う

| 意味         | 色（ライト／ダーク）                                 | 一緒に使う形                    | 使う場所                                   |
|--------------|------------------------------------------------------|---------------------------------|--------------------------------------------|
| 進学         | 青 `#2A78D6`／`#3987E5`（今のパレットの1番目）       | 角帽アイコン`HatGraduation`     | KPIカード、グラフ、一覧の行頭、検索の区分列 |
| 就職         | 橙 `#EB6834`／`#D95926`（今のパレットの2番目）       | かばんアイコン`Briefcase`       | 同上                                       |
| 合計         | 文字の第2色（灰色）                                  | 破線                            | 年度別の推移                               |
| 受験方法     | 今のパレットの3番目以降（緑・黄・桃・深緑・紫・赤）。「その他」は灰色 | 線の端の直接ラベル              | 受験方法別の推移                           |
| 増加・減少   | 文字色のまま                                          | ▲▼（`CaretUp`／`CaretDown`）  | KPIの前年度比、年度比較                    |
| 成功・注意・エラー | WPF UIのシステム色（`SystemFillColorSuccess`／`Caution`／`Critical`） | ✓・⚠・✕のアイコンと文字 | InfoBar、接続状態、合否バッジ               |

決まり：

1. **青と橙は「進学」「就職」専用にする。** 進学の受験方法の線や棒には使わない。受験方法「就職」は区分の「就職」と同じものなので、就職の橙を使う。
   進学の受験方法に使える色は残りの6色になるので、名前付きで表示するのは最大6種類にして、それ以外は灰色の「その他」にまとめる
   （今は「就職」を含めて上位7種類。実データの進学の受験方法は4種類なので、今は影響しない）。
2. **色だけで区別しない（WCAG 1.4.1、デジタル庁デザインシステム）。** 進学・就職は必ずアイコンか文字を一緒に出す。
   折れ線は線の端に系列名を直接書く。
3. **増減は良し悪しの色にしない。** 進路の件数が増えるのが良いとは限らないので、赤／緑は使わず▲▼と符号で示す。
   NN/gも、色で量の大小を表さないよう勧めている。
4. 色はコードに直接書かず、`App.xaml`のリソース（例：`StudyBrush`・`WorkBrush`）にまとめて、テーマごとに切り替える。
   グラフの`SeriesChartView`もこのリソースから色を取る。

## 5. 95点の判定基準

次をすべて満たしたら95点とする。

チェックは6章の実装後の状態。

- [x] ⓘは3個以下で、どれも定義・算出方法の補足だけ（制約・ルール・操作方法を含まない）。→ 2個（学科の求め方・増減率の式）。テストで確認。
- [x] 常に表示される説明の文章（句点で終わる文）は、エラー・空状態・警告のメッセージを除いて0。
- [ ] 同じ色が2つの意味を持たない。青は進学、橙は就職だけ。進学・就職を色だけで区別している所がない。
  → 色の意味はそろえた。ただし折れ線は、線そのものには名前がなく、凡例との色の対応とマウスを合わせたときの強調で見分ける（6.2）。
- [ ] 各画面を5秒見せて、「何年度の」「何の数で」「前と比べて増えたか減ったか」を答えられる。→ 利用者に試してもらう確認はまだ。

  → ボタンは満たした。ナビゲーションは、選択中の項目だけラベルが隠れる（WPF UIのLeftFluentの仕様。6.2）。
- [x] エラーのときは、何が起きたかと、次に押すボタンが画面に出ている。
- [x] 読み込み中・0件・エラーが、それぞれ違う見た目で表示される。
- [ ] キーボードだけで全ボタンとⓘに移動でき、フォーカスが見える。→ ⓘと年度の棒にフォーカス枠を付けた。キーボードだけで全画面を通す確認はまだ。
- [ ] ライト・ダーク・ハイコントラストで、上のすべてが成り立つ。→ ライトとダークは画面で確認した。ハイコントラストは未確認。

### 6.2 計画から変えたこと

- **折れ線の直接ラベル（A-6）は、凡例の位置の変更に置き換えた。** 実データでは進学（271件）と就職（237件）の線が近く、線の右端に名前を書くと文字が重なる。凡例をグラフの上に移し、各系列の最新値を添え、凡例にマウスを合わせると他の線が薄くなるようにした。
- **ナビゲーションの戻るボタンはなくなった。** WPF UIの`LeftFluent`には戻るボタンがない。また、選択中の項目はラベルが隠れてアイコンだけになる（ページ見出しで名前は分かる）。
- **受験方法の色は、少ない種類で色相が離れる順に割り当てた。** 緑・黄・桃・紫・赤・深緑の順で、4種類なら緑が2つ並ばない。名前付きで表示するのは最大6種類で、それ以上は灰色の「その他」にまとめる。
- **ダッシュボードの選択中の年度の棒は、強調色ではなく濃い文字色にした。** 強調色（青系）だと「青＝進学」と紛らわしいため。
- **CSV保存の通知に「フォルダーを開く」ボタンは付けていない。** WPF UIの`Snackbar`がボタンを持てないため。
- **WPF UIの`InfoBar`と`Badge`は使わなかった。** `InfoBar`は中にボタンを置けず、`Badge`は一部の配色で文字が見えなかったため、同じ見た目の部品を作った。
- **年度の手入力（`NumericOnlyBehavior`）を削除した。** 卒業年度が選択式になり、使う場所がなくなったため。

### 6.3 確認したこと

- `.\Run-App.ps1 -Verify -Database -Render`：186項目すべて成功（データベースなしでは163項目）。バインディングエラー0。
- 追加したテスト：前年度比・構成比、受験方法の区分ごとの一覧、年度の棒、年度比較のカードと受験方法別の増減、年度の入れ替え、範囲ボタンの選択状態、エラー・0件・中断・未検索の表示の違い、学科での検索（実データでは全学科で件数がグラフと一致）、区分列の件数、ⓘの数と読み上げ名、凡例の強調、テーマ切り替えでの意味の色。
- 実データ（6,020件・11年度）で、ダッシュボード・進路グラフ・年度比較の画面を確認した。検索・設定・ダーク表示は架空データの描画で確認した。
